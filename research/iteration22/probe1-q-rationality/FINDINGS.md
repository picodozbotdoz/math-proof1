## 2. The bridge that makes a *constructive rational* route cheap

The ℂ existence proof is non-constructive (cyclicity).  But a DIRECT rational
witness needs only:

1. **Representation**: `T (fb i) = ∑ j, (M i j : ℂ) • fb j` for the echelon
   basis `fb` and the integer matrix `M` — `CharpolyDimN.charpoly_dimN`
   (CharpolyDimN.lean:194) already consumes exactly the right hypotheses
   (`hzero/hone/hA/hX`) and internally performs the triangular
   back-substitution (`coord_eq`, :219), but it exports only the charpoly.
   A sibling exported lemma `represents_dimN : (same hyps) → ∀ i < n,
   T (f i) = ∑ j, (coordN … j) • f j` is ~40 lines in a NEW module (do NOT
   edit CharpolyDimN in place — new-module rule; check ancestors below).
   Needs: triangular independence of `{f i}` (distinct leading q-orders) +
   `finrank = n` ⟹ spanning ⟹ every `T (f i)` has a coordinate expansion;
   coordinates = back-substitution of the `X` table = integer entries.
2. **Operator equality from agreement on the basis**: two ℂ-linear maps equal
   on a spanning set are equal (Mathlib: `LinearMap.ext_on` + span, or
   `Submodule.span_eq_top` route) — routine.
3. **The rational witness + kernel certificate**: solve offline
   `∑_{j<n} q_j M₂^j = M₃` exactly over ℚ (unique because `charpoly M₂` is
   irreducible ⇒ `I, M₂, …, M₂^{n−1}` linearly independent); emit `Q : ℚ[X]`
   as a chunked literal and certify the scaled integer matrix identity
   `∑_j N_j • M₂^j = D • M₃` (N_j = q_j·D, D = common denominator) by
   `decide +kernel` per weight.

Then `aeval T₂ (Q.map (algebraMap ℚ ℂ)) = T₃` follows from 1+2+3 by
linearity (`M₂^j` acts as the j-th power — needs `aeval`-of-power ↔ matrix
power agreement on the basis; cleanest: prove `aeval T₂ (C c * X^j) (fb i)
= ∑ l (M₂^j)ₗᵢ • fb l` by induction on j using `represents` twice — ~30
lines generic).  Mathlib compat: `Polynomial.map_aeval_eq_aeval_map`
(AlgebraMap.lean:497) for the map-algebraMap plumbing.

## 6. Chosen route + blueprint shape

**Route: constructive rational witness + representation bridge** (NOT the
ℚ-span/ℚ-vector-space upgrade — that needs `W ⊗ ℂ ≅ S_k` formalization,
strictly more pain for the same statement).

* Objective: `∃ Q : ℚ[X], heckeTPₗ ((K : ℕ) : ℤ) Nat.prime_three
  = aeval (T₂ | S_K) (Q.map (algebraMap ℚ ℂ))` for all 54 weights 24–134
  (p = 3; the operator with a landed integer matrix; other primes follow the
  same recipe once their matrices exist — non-objective).
* Module layout: NEW light `HeckeRational.lean` (generic: represents-from-
  tables sibling of charpoly_dimN, aeval-power↔matrix-power, operator-eq
  from basis agreement — NO ancestor edits: CharpolyDimN is NOT an ancestor
  of the heavy MaedaGalois5 chain (checked against the AGENTS.md ancestor
  list), but the new-module rule is cheaper than proving that per edit);
  generated `HeckeRationalWeights.lean` (or per-dim split if CI cost demands)
  from a new `tools/gen_hecke_rat.py` (solve + assert + emit chunked
  literals + the scaled identity `decide +kernel`).
* Verification: Modal per-file green 0/0; AxCheckDecide combined; tauceti
  audit; registration decision by measured CI add (root-only if > ~10 min).
* Stage gates (each one green-commit session):
  G1 audit existing small-weight T₂ matrices + re-derive all (M₂, M₃) pairs
  against Lean literals; G2 generic module green (local lean file + Modal);
  G3 generator + dims 6–10 (30 weights) green; G4 small weights or recorded
  descope; G5 registration + audits + bookkeeping.
* Risks: (a) dim-10 scaled-identity decide heavier than projected — split
  per weight or fall back to per-cell `norm_num` chunks; (b) small-weight T₂
  matrix audit fails — descope to 30 weights; (c) heartbeat on the big file —
  split per-dim (established pattern).  All fallbacks inside light-module
  rules (no set_option).
