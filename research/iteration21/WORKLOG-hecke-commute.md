## Design decisions (up front)

- **Commutativity** (`MathProof/ModularForms/HeckeCommute.lean`, light):
  coefficient-comparison via `heckeTP_qExpansion_coeff` unrolled twice, then
  q-expansion injectivity (`ModularForm.qExpansion_injective`, lifted to
  cusp forms through `CuspForm.toModularFormₗ` — both at the pin).
  Full generality `∀ p q primes` (the `p = q` trap dissolves: after `subst`
  both composed expansions are syntactically identical; the `p ≠ q` case is a
  4-branch `p ∣ m` / `q ∣ m` split with `Nat.mul_div_cancel_left` rewrites).
- **Upgrade** (`MathProof/ModularForms/HeckeGeneratedByT2.lean` + generated
  `HeckeGeneratedByT2Weights.lean`, both light): the blueprint's literal
  `∃ Q : ℚ[X], T_p = aeval T₂ Q` is type-incorrect (`S_k` is a ℂ-space;
  charpoly/aeval need the scalar field).  Delivered: `∃ Q : ℂ[X], …` via
  - `exists_aeval_of_commute_of_minpoly_eq_charpoly` — the HeckeAlgebraQT2
    upgrade restated with `minpoly = charpoly` (cyclic operator); the cyclic
    vector comes from the PIN's `Module.exists_ker_toSpanSingleton_eq_annihilator`
    (PID structure theorem) applied to `Module.AEval' T₂` — NO per-weight
    ℚ-structure needed;
  - `minpoly_eq_charpoly_of_map_of_irreducible` — over ℂ: `P_ℚ` irreducible ⟹
    separable ⟹ `natDegree`-many distinct ℂ-roots; each root of charpoly is an
    eigenvalue (`Module.End.hasEigenvalue_iff_isRoot_charpoly`) hence a root of
    minpoly (`Module.End.isRoot_of_hasEigenvalue`); degree count + monic finish;
  - wrapper `heckeTP_mem_spanT2` (weight-generic) fed by
    `heckeTPₗ_commute` + per-weight `charpoly_T2`/`maeda` theorems.
- 54 instances: 24; 28..50 (11, SmallWeights); 48..134 (42, Dim4..10Weights)
  — every even weight 24..134.  Generated by `tools/gen_hecke_gen_t2.py`
  (`--check` byte-identity verified).

Deviations from the blueprint:
1. `∃ Q : ℚ[X]` delivered as `∃ Q : ℂ[X]` (the ℚ-form is type-incorrect for a
   ℂ-linear `T₂`; see research-log entry for the rationality follow-up note).
2. The upgrade goes through `minpoly = charpoly` (cyclicity) instead of
   irreducibility of the charpoly over ℂ — the latter is FALSE for dim ≥ 2
   over an algebraically closed field; this is the blueprint R1 risk,
   resolved via the eigenvalue route + PID cyclic vector (no per-weight
   rational structures, no changes to the generated Maeda files).
3. `tools/modal_run.sh` could not be used verbatim from a worktree (mirror
   `.git` is a dangling pointer file for the mirror user); equivalent
   clone+rsync mirror at the base commit, same lean_check semantics.
