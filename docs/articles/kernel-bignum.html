Multiplying polynomials inside a proof kernel

Packing a whole polynomial into one integer took the kernel-verified bound for τ from 512 to 65,536, a 128-fold gain, after list arithmetic had failed above 71 GB.

WHAT IS PROVED

tau_ne_zero_of_le_65536: τ(n) ≠ 0 for all 1 ≤ n ≤ 65536, by decide +kernel, with no native_decide and no external computer algebra. Run the module's #print axioms lines for its exact axiom list.

A proof kernel is designed to be small and trustworthy, not fast. It evaluates programs by rewriting terms. Under the project's rules, every computation had to run there, so the question was practical: how far can the kernel compute coefficients of Δ?

The 16,384 and 65,536 rows include the module's earlier decisions. The bound rose 128-fold from the list method, and the last step cost far less than extrapolating that method would have.

Why more tuning could not help

The study tested the usual suggestions and measured each one. Strict forcing helped by a factor of 2 to 3 but could not finish. Tail recursion changes nothing, because the kernel is lazy and an unforced accumulator just builds a longer chain of suspensions. UInt64 was a misdiagnosis, because values already fit in one machine word and the kernel's fast path is for Nat. The cost was the sheer number of reduction steps, each one retained until the end (the memory law).

So the only fix was to change the data so that far fewer kernel steps were needed.

The idea: make one multiplication do it all

Lean's kernel has one great asset. Arithmetic on Nat literals is delegated to GMP, the fast bignum library. A single huge multiplication is one kernel step. So pack a whole polynomial into a single number:

[c₀, c₁, c₂, …]  ⟼  c₀ + 2⁸⁰·c₁ + 2¹⁶⁰·c₂ + …

Multiplying two such numbers multiplies the polynomials, as long as coefficients do not overflow their 80-bit slots. This is the classical trick called Kronecker substitution. With coefficients below P = 999999937 and d ≤ 65536 terms, each slot stays below d·(P−1)² < 2⁷⁶ < 2⁸⁰, and Lean proves that bound (convSum_lt). A convolution with about 4 billion terms became one Nat.mul.

Three more pieces

  • Pentagonal numbers. Euler's theorem says ∏(1 − qm) has coefficients ±1 at generalized pentagonal indices and 0 elsewhere, and Mathlib has this. The whole first phase needs no multiplication.
  • Five products. The 24th power uses 24 = 16 + 8: four squarings and one product.
  • Balanced packing. Packing by divide and conquer rather than a linear walk cut isolated packing memory from 3.4 GiB to 1.0 GiB at 16,384.

Two details are easy to miss. Core Nat.sqrt is defined by well-founded recursion, which the kernel cannot reduce, so the project wrote a structurally recursive Newton square root. And a nonzero residue mod a prime certifies a nonzero integer, so no size bound on τ is ever needed.

The attractive certificate that would have been wrong

A cheaper-sounding plan was to check the identity by evaluating both sides at d points. It is unsound here. Evaluating a power series truncated at degree d aliases its coefficients, so the check would certify Σk fi+kd rather than fi, and a zero of τ could hide behind cancellation. Convolution checking verifies the actual truncated coefficients.

WHAT YOU ARE TRUSTING

The kernel's GMP acceleration is part of Lean's trusted base, so a GMP bug could in principle affect this result. That risk is much smaller than trusting a compiler with native_decide, but it is not zero. The verified bound is also tiny next to unverified records. What this article describes is a technique, and it applies to any kernel computation that reduces to large convolutions.
